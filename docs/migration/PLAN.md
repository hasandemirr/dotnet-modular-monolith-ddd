# Migration Plan - OperationsSuite platform -> dotnet-modular-monolith-ddd

Temporary document. It is deleted in Step 12.

## 1. Scope

- Source: OperationsSuite, platform parts only (D-006).
- Target: this repository, root namespace `ModularMonolith` (D-008).
- Method: additive transfer (D-003) executed by Claude Code (D-004).
- Findings below come from the source repomix snapshot. Items marked **verify** were
  not fully visible there and must be checked against the source export before acting.

## 2. Preconditions (owner)

1. Commit all VM-only fixes to the source repository so the export is current (D-005).
2. Export the source: `git archive --format=zip --output ../source-reference.zip HEAD`
   in the source repository. Extract it next to this repository.
3. In the extracted copy, delete `Infrastructure/Migrations/` and every folder named
   `SeedData`.
4. Create this GitHub repository as private (D-011).
5. Start Claude Code in this repository and add the extracted copy as an additional
   working directory. Make the extracted copy a local git repository with one baseline
   commit (`git add -A --force`), so any change shows in
   `git -C ../source-reference status`.
6. Upload `CLAUDE.md`, `docs/decisions.md`, this plan and
   `repomix-source-reference.xml` to the chat project.

## 3. Per-step loop

1. The chat project produces the Claude Code prompt for one step (or sub-step).
2. Claude Code shows its plan for the step: files to copy, files to skip, changes.
   The owner approves.
3. Claude Code applies the plan and runs the verification commands.
4. Claude Code writes the transfer report (section 7).
5. Independent review in the chat project (repomix of this repository or the diff),
   against the step's acceptance criteria and the `CLAUDE.md` checklist.
6. The owner commits (D-010) and pushes.

One step per Claude Code session. One change per turn. The next step's prompt is not
written before the current step is closed.

## 4. Definition of done (every step)

- `dotnet build`: 0 errors; warnings listed in the transfer report.
- `dotnet test`: all tests pass. Behavior changed in the step is covered by a test
  added in the same step (the test project exists from Step 0).
- Forbidden-pattern grep (`CLAUDE.md`, Verification): no hit outside the allow-list
  in `CLAUDE.md`, Testability.
- Non-ASCII grep on `src` and `tests`: no hit.
- Trace grep (section 5): no hit.
- Transfer report written; independent review passed; owner committed.

Source: `src/OperationsSuite.Api/`

7a - Common, as-is (review each file):

  `EnsureRolesAsync` before `EnsureAdminUserAsync`. If the Development migration runs
  inside `EnsureAdminUserAsync`, startup on an empty database fails; **verify** and fix
  the order.

7b - Middleware fixes:
- Error statuses produced without an exception (404 from `Results.NotFound()`, 401/403
  from authentication, 429 from the rate limiter) return no body. Every error status
  returns ProblemDetails with `correlationId` (built-in ProblemDetails services and
  status code pages).
- `IdempotencyMiddleware` caches only the status code, so a replay returns no body.
  Cache status, body and content type; scope the key by user, method and path.

7c - Endpoints: `Endpoints/Auth/`, `Endpoints/Authz/RolesEndpoints.cs`,
`Endpoints/Users/UsersEndpoints.cs` (**verify**, not reviewed in detail),
`Endpoints/Approval/` if P-01 keeps it. Check every endpoint against the endpoint
standard.

7d - `Program.cs` and configuration:
- Remove domain module registrations and `UserProvisioningOrchestrator`.
- `ForwardedHeadersOptions` is built but `UseForwardedHeaders` is never called; call
  it. `KnownNetworks` is hard-coded to `172.18.0.0/16`; move it to configuration.
- The `"auth"` rate limiter has no partition (one bucket shared by every client);
  partition by client IP.
- Remove `AddPolicy("admin", p => p.RequireRole("admin"))` (role-string check).
- `appsettings.json`, `appsettings.Development.json`: remove company values, the
  `ApplicationInsights` section and `AdminSeed:Password` (no matching option); use
  neutral placeholders.
- `Properties/launchSettings.json` and `OperationsSuite.Api.csproj`: review.
